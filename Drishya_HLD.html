01. Project Overview

Drishya is a full-stack, enterprise-grade video-sharing and creator ecosystem. It empowers digital creators to monetize content through customized membership tiers, engage fans via interactive community polls, and leverage a dedicated AI Creator Assistant powered by Retrieval-Augmented Generation (RAG) with FAISS vector search, Google Gemini LLMs, and FLUX.1 [dev] photorealistic thumbnail synthesis.

Key System Capabilities

  • Modern Neumorphic Design System: Tactile extruded card surfaces, carved-in inset inputs, physical pressed states, dual-mode light/dark elevation, and strict WCAG AA contrast compliance while preserving the brand color palette.
  • RAG-Powered AI Creator Assistant: Ingests trending YouTube statistics into a local FAISS vector store with LangChain and Sentence-Transformers, dynamically retrieving contextual creator patterns to ground LLM generation.
  • FLUX.1 [dev] Thumbnail Engine: High-resolution 16:9 widescreen photorealistic thumbnail image generation via fal.ai API with visual chips and layout guidance.
  • Video Streaming & Access Control: Stream public and members-only videos with server-side URL obfuscation and tier-based entitlement checks.
  • Razorpay Payments: Full subscription lifecycle verified via server-side HMAC-SHA256 signatures and webhook handlers.
  • Interactive Community Polls: Tactile creator polls with live vote switching, percentage fills, and optimistic client updates.
  • Dual Authentication: Clerk OAuth (Google, Apple, GitHub) alongside local JWT dual-token authentication.

07. Authentication Architecture

Drishya supports a hybrid authentication paradigm offering native Dual JWT Token security alongside federated Clerk OAuth integration.

7.1 Native Dual JWT Token Strategy

  • Access Token: Short-lived JWT (1 day) containing user identity and role payload, delivered via HTTP-Only cookies or Authorization: Bearer headers for low-latency stateless verification.
  • Refresh Token: Long-lived JWT (10 days) stored securely in the database User.refreshToken field. Enables silent session renewals via POST /api/v1/users/refresh-token and provides instant session revocation upon signout.
  • Credential Security: Passwords hashed with bcrypt (10 salt rounds) with pre-save mongoose middleware.

7.2 Clerk OAuth Integration

For seamless one-click social authentication (Google, GitHub), Drishya embeds @clerk/react. The custom useAuth hook normalizes auth states across both Clerk and local JWTs, ensuring unified user profiles and graceful logout synchronization.

08. Video Upload & Playback Flow

8.1 Multi-Part Upload Pipeline (Multer -> Cloudinary)

  1. Client Dispatch: The creator initiates upload via POST /api/v1/videos with video and thumbnail binary buffers along with title, description, and visibility parameters.
  2. Multer Staging: Video files are staged to local temporary storage (public/temp) with disk storage engine.
  3. Cloudinary Ingestion: The utility uploadOnCloudinary streams the asset using chunked transfer (resource_type: "video"), extracting duration, frame rates, and CDN URLs.
  4. Automatic Cleanup: Temporary local files are guaranteed to un-link immediately via fs.unlinkSync(localFilePath) in try/catch/finally blocks to avoid disk exhaustion.
  5. Database Record: A new document is saved in the Video collection containing visibility tiers, duration, Cloudinary URLs, and owner reference.

8.2 Playback & Entitlement Enforcement

Video streaming operates under strict entitlement checks: public videos stream instantly, while members-only and tier-only videos verify active subscription records. If the viewer is unauthorized, the server strips videoFile = null, prompting a tactile membership purchase modal.

10. AI Microservice & RAG Vector Architecture

The Drishya AI Microservice is an independent high-throughput Python service built on FastAPI and Uvicorn (port 8001). It powers the creator assistant through a state-of-the-art Retrieval-Augmented Generation (RAG) pipeline utilizing FAISS, LangChain, Google Gemini 2.5 Flash, and the FLUX.1 [dev] photorealistic image synthesis engine.

10.1 Retrieval-Augmented Generation (RAG) Pipeline

Standard LLMs frequently hallucinate or generate generic, outdated YouTube titles and content concepts. Drishya solves this by grounding all generation tasks with a local FAISS vector database populated with verified trending creator datasets:

  • Dense Embeddings: all-MiniLM-L6-v2 transforms video titles, descriptions, and tags into 384-dimensional dense vector spaces with low inference latency (<15ms).
  • FAISS Vector Store (faiss_index/): Employs an exact L2 distance index (IndexFlatL2) serialized into index.faiss alongside metadata pickle mappings (index.pkl).
  • Contextual Prompt Injection: Retrieved trending titles provide domain-specific CTR structures, hook patterns, and keyword densities directly to the prompt instructions.

10.2 Multimodal LLM Cascade & Resiliency

The microservice operates an automated multi-tier model fallback cascade to guarantee 99.9% availability:

  1. Primary Model: gemini-2.5-flash via the official Google Generative AI SDK, executed asynchronously using asyncio.to_thread to maintain non-blocking event loops.
  2. Secondary Model: Automatic fallback to gemini-1.5-flash if the primary model encounters rate limits or quota throttling.
  3. Algorithmic Fallback: If third-party LLM APIs are unreachable, a deterministic template engine synthesizes high-retention title variations and roadmap milestones to prevent user-facing errors.

10.3 FLUX.1 [dev] Thumbnail Synthesis Engine (image_gen.py)

Thumbnail generation transcends simple prompt formatting by integrating the state-of-the-art FLUX.1 [dev] diffusion model via fal.ai:

  • Aspect Ratio: Locked strictly to 16:9 widescreen standard (1280x720 / 1920x1080) for native YouTube video compliance.
  • Photographic Prompt Synthesizer: Takes creator topic, category, and visual mood (e.g. "Cinematic Cyberpunk", "Clean Minimalist Tech") and formats detailed photographic specs including rim lighting, depth of field, typography composition, and color grading.
  • Structured Metadata: Returns the generated high-resolution hosted image URL alongside layout placement recommendations (e.g. "Rule of Thirds - Left Subject") and color palette tags.

11. Membership & Payment Architecture

Drishya empowers content creators to monetize their work directly through customized recurring membership tiers, backed by Razorpay and server-side cryptographic verification.

11.1 Tier Structure & Hierarchy

Creators configure hierarchical membership tiers (e.g. Bronze, Silver, Gold) stored in the MembershipTier collection. Each tier defines:

  • Rank: Numeric hierarchy (e.g., Bronze = 1, Silver = 2, Gold = 3) used for comparative entitlement checks.
  • Pricing & Currency: Monthly fee in INR (converted to paise for Razorpay order initialization).
  • Perks & Visual Identity: Distinct hex accent colors, badge icons, and bulleted creator benefits.

11.2 Razorpay Order Creation & Verification Flow

  1. Order Initialization: Frontend triggers POST /api/v1/payments/create-order with creatorId and tierId. Backend calls Razorpay API: 
    const order = await razorpay.orders.create({ amount: tier.price * 100, currency: "INR", receipt: `rcpt_${Date.now()}` });
  2. Client Checkout: The frontend opens the Razorpay modal. Upon successful client payment, Razorpay returns razorpay_order_id, razorpay_payment_id, and razorpay_signature.
  3. HMAC-SHA256 Cryptographic Verification: Client submits payment credentials to POST /api/v1/payments/verify. The backend verifies authentic origin: 
    const expectedSignature = crypto
  .createHmac("sha256", process.env.RAZORPAY_KEY_SECRET)
  .update(`${order_id}|${payment_id}`)
  .digest("hex");

if (expectedSignature !== signature) throw new ApiError(400, "Invalid payment signature");
  4. Activation: On signature match, the backend upserts a Membership record with status: 'ACTIVE', set expiration (30 days rolling), and writes an immutable audit record to PaymentLog.

12. Members-Only Content Access Control

Drishya implements strict zero-trust media protection through Server-Side URL Obfuscation, preventing unauthorized users from accessing Cloudinary video stream assets.

12.1 Visibility Levels

Visibility Enum Access Criteria Unauthenticated Behavior
PUBLIC Open to all platform visitors and unregistered guests. Full metadata and streaming video URL delivered.
MEMBERS_ONLY Requires any active tier membership with the video's creator. videoFile: null, isLocked: true. Prompted to join channel.
TIER_ONLY Requires membership with tier.rank >= video.minimumTier.rank. videoFile: null, isLocked: true. Prompted with minimum required tier.

12.2 Server-Side URL Stripping & UI Guard

When getVideoById resolves a request:

  • If the user is the video owner, immediate full access is granted.
  • If the user is unauthorized (unauthenticated, non-member, or tier rank too low), the backend sets videoData.videoFile = null and populates isAuthorized = false with a descriptive accessReason before sending the response.
  • The frontend player receives null media streams, rendering a tactile neumorphic lock overlay with creator tier checkout triggers (MembershipModal.jsx). Streaming URLs are never exposed in browser developer tools for locked videos.
  • For authorized users, view counts are atomically incremented only once per user via the viewedBy set.

14. Deployment Architecture

Drishya supports decoupled containerized and multi-node cloud deployments:

  • Frontend: Vercel or Netlify with automatic HTTPS and global edge CDN caching.
  • Backend API: Render or AWS EC2 running Node.js 20+ with cluster mode or PM2 process management.
  • AI Microservice: Railway, Render, or DigitalOcean Droplet running Python 3.11 with pre-built FAISS wheels and Sentence-Transformers cache.
  • Data Stores: MongoDB Atlas (M0/M10 replica set) and Cloudinary media CDN.

15. Security Architecture

  • Password Protection: Hashed using bcrypt with salt factor 10.
  • JWT Token Guards: AccessTokens (1-day expiration); RefreshTokens stored hashed in database for revoking compromised sessions.
  • HMAC Signature Verification: Payments verified server-side using crypto.createHmac('sha256') against Razorpay webhooks and client payloads.
  • Server-Side URL Obfuscation: Unauthorized requests for protected creator videos receive videoFile: null to prevent media scraping.
  • CORS Hardening: Configured strictly for authorized frontend domains (e.g. http://localhost:3000, http://localhost:3001).

20. "How Drishya Works" — Developer Onboarding

A quick 5-step operational mental model for engineers contributing to Drishya:

  1. Step 1 — Build the FAISS Vector Index: Run python ai-service/scripts/ingest.py to embed trending creator datasets using sentence-transformers into faiss_index/index.faiss.
  2. Step 2 — Launch the AI Microservice: Start FastAPI at http://localhost:8001 via uvicorn main:app --port 8001 --reload. Verifies FAISS vector store liveness at /health.
  3. Step 3 — Start the Node/Express Backend: Run npm run dev in backend/ on port 8000. Connects to MongoDB Atlas and mounts routes with auth guards.
  4. Step 4 — Start the React Neumorphic SPA: Run npm run dev in frontend/ on port 3000/3001. All components consume tokens from tokens.css with dual-mode tactile lighting.
  5. Step 5 — Run Integration Tests: Execute pytest tests/test_rag.py to verify that RAG vector search, context augmentation, and generation contracts pass.
