01. Project Overview

Drishya is a full-stack, enterprise-grade video-sharing and creator ecosystem. It empowers digital creators to monetize content through customized membership tiers, engage fans via interactive community polls, and leverage Google Gemini AI microservices for automated title, content idea, and thumbnail generation.

Key System Capabilities

  • Video Streaming & Access Control: Stream public and members-only videos with server-side URL obfuscation.
  • Razorpay Payments: Full subscription lifecycle verified via server-side HMAC-SHA256 signatures and webhooks.
  • Interactive Community Polls: Editable creator polls with zero initial fake votes, live vote switching, and real-time percentage progress bars.
  • AI Microservice (FastAPI): Powered by Google Gemini 2.5 Flash for asynchronous content recommendations and thumbnail prompt design.

03. Overall System Architecture

The Drishya system comprises three distinct operational layers: the React SPA Frontend, Node/Express Core Backend API, and FastAPI AI Microservice, connected to MongoDB Atlas and Cloudinary media services.

04. Frontend Architecture

The React SPA uses modular components, Zustand store for state management, and Axios interceptors for authenticated REST requests.

05. Backend Architecture

The Express.js server implements an asynchronous controller-service pattern with centralized error handling via asyncHandler and ApiError abstractions.

06. Database Design (ER Diagram)

The MongoDB database contains 10 primary collections with indexed references ensuring relational integrity across users, memberships, and videos.

07. Authentication Flow

Authentication utilizes Dual JWT Tokens (AccessToken in HTTP-Only cookies/bearer headers + RefreshToken stored in Database).

08. Video Upload & Playback Flow

Video uploads use Multer temporary disk storage, streamed to Cloudinary via chunking, and saved into MongoDB with permission flags.

09. Community Architecture

Community posts (Tweets and Editable Polls) operate over REST API endpoints (/api/v1/tweets). Embedded poll metadata is serialized into JSON payloads and managed dynamically on the client side.

Architecture Note: Real-Time WebSockets

Current community updates operate via optimistic REST API polling. WebSockets (Socket.io) are documented under Section 19 (Future Enhancements).

10. AI Microservice Architecture

The AI Microservice runs on FastAPI (port 8001) using non-blocking asynchronous execution (asyncio.to_thread) with gemini-2.5-flash as primary model and gemini-3.5-flash-lite as fallback model.

11. Membership & Payment Architecture

Creator memberships use Razorpay Orders API with server-side HMAC-SHA256 signature verification and webhook integration.

12. Members-Only Content Access Control

Backend enforces strict authorization rules: unauthorized users requesting MEMBERS_ONLY or TIER_ONLY videos receive videoFile: null in the JSON payload.

14. Deployment Architecture

Drishya supports containerized and multi-node cloud deployments (e.g. Vercel for Frontend, Render/AWS EC2 for Node Backend, and Railway/DigitalOcean for FastAPI AI microservice).

15. Security Architecture

  • Password Protection: Hashed using bcrypt with salt factor 10.
  • JWT Token Guards: AccessTokens expire in 1 day; RefreshTokens stored securely in DB.
  • HMAC Signature Verification: Payments verified server-side using crypto.createHmac('sha256').
  • CORS Hardening: Configured for specified origins (e.g. http://localhost:3000).

20. "How Drishya Works" — Developer Onboarding

A quick 4-step mental model for developers new to the Drishya repository:

  1. Client App Initialization: React SPA initializes at http://localhost:3000, checks JWT auth state via useAuthStore, and renders custom navigation.
  2. Request Processing: API requests route to Node/Express backend at http://localhost:8000/api/v1. Auth middleware validates tokens against MongoDB Atlas.
  3. AI Microservice Operations: Creators requesting AI title/content generation trigger async requests to FastAPI at http://localhost:8001/api/v1/generate/* which queries Gemini 2.5 Flash.
  4. Monetization & Access Guard: Creators define tiers via Razorpay. When users request protected videos, backend checks active membership records in MongoDB before serving media stream URLs.
